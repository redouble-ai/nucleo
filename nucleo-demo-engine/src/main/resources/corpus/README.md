# Halcyon Bicycle Works - shared drive

This directory is the demo's corpus: the kind of mixed folder a small company accumulates.
Everything in it is invented. Halcyon Bicycle Works does not exist, and neither do its
dealers, suppliers, customers or bank details.

What is here, and which tier of the extractor reads it. A file's first bytes decide the
route, never its extension, so the two that lie are caught before any model is asked:

| File | What it is | Tier |
|---|---|---|
| `README.md`, `meeting-notes-2026-02.md`, `minutes-2026-05-06.md`, `warranty-policy.txt`, `changelog.txt` | prose | read by code |
| `dealers.csv`, `inventory.json`, `application.yaml`, `build.properties` | data and config | read by code |
| `FrameSerial.java`, `pricing.sql`, `deploy.sh` | source | read by code |
| `workshop.log` | a log | read by code |
| `product-spec.docx`, `price-list.xlsx`, `dealer-pitch.pptx` | Office documents | read by code, through POI |
| `invoice-0417.pdf` | a PDF with a text layer | read by code, through PDFBox |
| `mixed-report.pdf` | page one has a text layer, page two is a scanned sheet | code reads page one, a vision-capable model page two, the report carries both |
| `scanned-letter.pdf` | a PDF that is a picture of a letter | a vision-capable model |
| `shop-sign.png`, `warranty-card.jpg`, `whiteboard.jpg` | photographs with text on them | a vision-capable model |
| `screenshot-prices.png` | a screenshot of a price table | a vision-capable model, which reads the table back as rows |
| `notes.txt` | a JPEG under a text extension | sniffed as an image, a vision-capable model |
| `sky.png` | an image with no text | a vision-capable model, which says so |
| `supplier-terms.notes`, `old-prices.bak` | text under extensions the code does not know | the classifier, then code |
| `telemetry.dat`, `keys.enc` | unsigned binaries | the classifier, then skipped |
| `empty.txt` | nothing | read by code, nothing to index |

Thirty files: eighteen the code reads alone, eight that need a model that can see (one of
them for a single page), and four that need a model to judge. The binaries, the Office
files, the PDFs and the images are generated by `../corpus-build/build-corpus.py`; the prose,
data and source files are authored. Point the extractor at this directory first, then at
your own.

The prices in these files are placed with a history behind them: lists that replaced one
another, a change decided in a meeting and repeated elsewhere, a later change decided as a
percentage in minutes whose only date is their file name, a proposal, a figure a sign says
used to apply, supplier costs, a model no longer sold. The second demo reads them back into
current and former prices; `build-corpus.py` says which file carries what. The story is
written to be answered for 1 June 2026, the day the last decided price takes effect: the
pricing steps open on that day, and on it every list is current or superseded and every
later figure is a proposal.
